# 12 · 验证与调试

> 每次适配后端后、或排查问题时，按本流程逐项执行。目标是「控制台 0 报错 + 后端日志有连接 + 数据真正落盘」。

## 1. 静态检查

```bash
cd D:\code\licode\nuxtweb

# 类型检查（vue-tsc）
npx nuxt typecheck

# 生产构建
npm run build
#   → node .output/server/index.mjs 可跑（.output/ 已生成）

# 静态产物（内嵌到 Go 二进制用，见 13 文档）
npm run generate
#   → dist/（index.html + 200/404.html + login/ + _nuxt/）
```

后端：
```bash
cd D:\licode
set GOPROXY=https://goproxy.cn,direct&& go build ./...
go test ./...
```

```bash
# 后端（临时目录放二进制，避免污染仓库）
```

## 4. WS 冒烟（node，用 ws 包；能带 cookie 才是完整链路）

```js
// ws-check.mjs（放在 nuxtweb 下以解析 ws）
import WebSocket from 'ws'
// 登录拿 cookie
const r = await fetch('http://localhost:3000/signin', {
  method:'POST', headers:{'content-type':'application/json'},
  body: JSON.stringify({ username:'licode', password:'123' }) })
const cookie = r.headers.get('set-cookie').split(';')[0]
const ws = new WebSocket('ws://localhost:3000/ws', { headers:{ Cookie: cookie } })
ws.on('open', () => {
  console.log('OPEN')                          // 期望：OPEN + settings/sessions 事件
  ws.send(JSON.stringify({ type:'settings_get' }))
  ws.send(JSON.stringify({ type:'sessions_get' }))
})
ws.on('message', d => console.log('EVENT', d.toString().slice(0,80)))
setTimeout(()=>process.exit(0), 4000)
```
判读：
- 打印 `OPEN` + `settings`/`sessions` 事件 → 中继 OK。
- **同时看后端日志**出现 `客户端已连接（当前 N 个）` → 认证+中继全通。
- 只 `OPEN` 无事件 → 消息未转发（检查 ws.get.ts 排队/readyState）。
- 不 `OPEN` → cookie 没带上（signin 修复？ws.get.ts 透传？）。

## 5. 无头浏览器全流程（puppeteer-core + Edge）

前置：`npm i -D puppeteer-core`（装到临时目录或项目），用系统 Edge：
```js
const puppeteer = require('puppeteer-core')
launch({ executablePath:'C:\\Program Files (x86)\\Microsoft\\Edge\\Application\\msedge.exe',
         headless:'new', args:['--no-sandbox','--disable-gpu'] })
page.on('console', m=>logs.push(`[${m.type()}] ${m.text()}`))
page.on('pageerror', e=>logs.push(`[pageerror] ${e.message}`))
page.on('requestfailed', r=>logs.push(`[reqfail] ${r.url()} ${r.failure()?.errorText||''}`))
```

流程要点：
1. `goto('http://localhost:3000/')` → 若跳 `/login`：`type('input[type="password"]','123')` → 点「登录」。
   - ⚠ 用户名框**默认已预填 `licode`**，**不要**再 `page.type` 用户名（否则变成 `licodelicode`）。
2. 断言首页文案（「本地 AI 编程助手」「已连接」）。
3. 设置：点 `button[title="设置"]` → 断言 input 存在 → 改一个数字字段 → 保存 → toast「设置已保存」→ 重开确认。
   - ⚠ 改完记得**恢复原值**（会真实写 `~/.licode/config.json`）。
4. 聊天：`textarea` 输入 + Enter → 等流式输出 → 断言出现 AI 回复。
5. 文件：点 `button[title="文件"]` → 断言出现 nuxtweb/docs 目录 → 进子目录 → 「上级」回退。
6. 搜索：点面板「搜索」tab → 断言引擎 chips（必应/百度/DuckDuckGo/本地库）→ 搜索返回结果。
7. 审计：tab → 断言「开始审计」「扫描目录」。

判读：`LOGS` 必须为空（0 error/warn）；`pageerror`/`requestfailed` 为空。
- 允许的噪声：登录前一次 `401`（`/api/version` 未登录探测）；`<Suspense>` info；vite connecting（debug）。

## 6. 调试技巧

| 目标 | 手法 |
| --- | --- |
| 看前端发了什么 | puppeteer `page.on('request')` 打印 `r.postData()`/`headers` |
| 看后端收到什么 | 后端 `~/.licode/logs/licode.log` + 控制台日志（`客户端已连接`） |
| 看 WS 中继通不通 | `curl http://localhost:3000/ws` → 应 426（crossws 路由在）；200 HTML = 没路由 |
| 改后端逻辑快速验证 | `go build` 新 exe → 重启后端（先 `taskkill /f /im licode-new.exe`） |
| 清理端口 | `netstat -ano | findstr :3000` → `taskkill /f /pid <pid>` |
| 类型/模板错误 | `npx nuxt typecheck`（fuxsto 未知组件不报，靠浏览器 console 抓） |

## 7. 配置保护

- `~/.licode/config.json` 含真实 api_key：**任何写测试前先备份**，测试后恢复。
- 恢复示例：
  ```bash
  copy %USERPROFILE%\.licode\config.json %TEMP%\opencode\config.bak
  ... 测试 ...
  copy /y %TEMP%\opencode\config.bak %USERPROFILE%\.licode\config.json
  ```
- 后台程序在跑时改文件后，记得**重启后端**让它重新加载。

## 8. 静态内嵌（形态 B）验证

前置：`npm run generate` 产出 `dist/` → `scripts/sync-nuxt.sh` 同步到 `internal/web/nuxt` → `go build`。

```bash
# 后端启动（静态内嵌模式，端口 8090 避开 8080）
go build -o %TEMP%\opencode\licode-test.exe .
start /b cmd /c "%TEMP%\opencode\licode-test.exe --host 127.0.0.1 --port 8090 [--password 123]"

# 冒烟（curl，见 13 文档 §6）
curl -s http://127.0.0.1:8090/ | findstr __nuxt                    # Nuxt SPA 壳
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:8090/_nuxt/entry.C2l30Q3j.css  # 200
curl -s http://127.0.0.1:8090/nonexistent | findstr __nuxt          # SPA fallback → index.html
curl -s http://127.0.0.1:8090/api/version                          # JSON（同源直连）
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:8090/ws           # 400（无 upgrade 头，路由在）

# 启用密码时：/ 未登录 → 302 /login；POST /login 正确 → 302 / + Set-Cookie
curl -s -D - -o NUL -X POST -d "username=licode&password=123" http://127.0.0.1:8090/login | findstr /i "location set-cookie"
```

判读：
- `_nuxt` 资源必须 **200**（否则是 `go:embed` 少了 `all:` 前缀，见 11 §38）。
- 任意未知路径回 `index.html`（SPA fallback）。
- `/login` 静态内嵌下走**原生 form**，无需 `/signin`。
