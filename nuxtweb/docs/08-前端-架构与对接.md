## 2. 与后端对接总表

| 流量 | 开发（npm run dev） | 生产（node .output/server/index.mjs） |
| --- | --- | --- |
| REST `/api/*` | nitro `devProxy` | nitro `routeRules` proxy |
| WS `/ws` | CLI 转发 upgrade → worker 的 crossws 中继 | node-server preset 原生 upgrade → crossws 中继 |
| 登录 `/signin` | `server/routes/signin.post.ts` | 同左 |

## 3. nuxt.config.ts 逐段解析

```ts
import http from 'node:http'
import tailwindcss from '@tailwindcss/vite'

const backend = process.env.LICODE_BACKEND || 'http://127.0.0.1:8080'
```
- `LICODE_BACKEND` 环境变量决定后端地址；`runtimeConfig.public.licodeBackend` 暴露给前端展示连接横幅。

```ts
export default defineNuxtConfig({
  compatibilityDate: '2025-07-15',
  devtools: { enabled: false },
  ssr: false,                       // 纯 SPA，聊天流式内容不做 SSR
  css: ['~/assets/css/main.css'],
  runtimeConfig: { public: { licodeBackend: backend } },
  hooks: {
    listen(server) {
      // WS upgrade 兜底隧道：仅当外层 upgrade 无监听器时挂载（防与 CLI 转发双处理）
      const hasForwarding = server.listeners('upgrade').length > 0
      if (!hasForwarding) attachWsTunnel(server)
    },
  },
  vite: { plugins: [tailwindcss()] },   // ★ 必须，否则页面纯文本
  nitro: {
    experimental: { websocket: true },  // ★ 必须，否则 dev 不转发 WS upgrade
    devProxy: {                         // 挂载点语义会剥前缀 → target 带同名前缀
      '/api': { target: `${backend}/api`, changeOrigin: true },
      '/health': { target: `${backend}/health`, changeOrigin: true },
      '/ready': { target: `${backend}/ready`, changeOrigin: true },
    },
    routeRules: {                       // 生产代理
      '/api/**': { proxy: `${backend}/api/**` },
      '/health': { proxy: `${backend}/health` },
      '/ready': { proxy: `${backend}/ready` },
    },
  },
  app: { head: { title: 'licode', htmlAttrs:{lang:'zh-CN'}, ... } },
})
```

### 3.1 为什么 devProxy 的 target 要带前缀
nitro devProxy 把 key 当作 **h3 挂载点**：请求 `/api/auth` 会先被剥成 `/auth` 再转发；httpxy 再把 target 的路径前缀拼回。所以 target 必须写成 `${backend}/api`，最终才请求到 `http://127.0.0.1:8080/api/auth`。写成 `${backend}` 会让后端收到 `/auth` → 命中 `/` 兜底 → 返回 HTML（表现为「/api 返回 HTML」）。

### 3.2 WS upgrade 链路（dev）
1. `nitro.experimental.websocket: true` → worker 模板里 `import.meta._websocket` 为真 → 挂 crossws `upgrade` 处理。
2. @nuxt/cli 的 dev server 检测到 `nuxt.server.upgrade` 存在后，把外层 `upgrade` 事件转发给 worker。
3. worker 内 `server/routes/ws.get.ts` 的 `defineWebSocketHandler` 匹配 `/ws`，`open(peer)` 时建立到后端的 `ws` 客户端并**转发 cookie**，之后双向转发消息。

> 排查线索：GET `/ws` 若返回 **426**（Upgrade Required），说明 crossws 路由已生效；若一直 1006/无法升级，检查 `experimental.websocket` 是否开启、hooks 兜底隧道是否与 CLI 转发叠加（两个 upgrade 监听器同时处理同一 socket → 帧损坏）。

### 3.3 WS 中继实现（server/routes/ws.get.ts）
```ts
import { WebSocket as WsClient } from 'ws'
const sockets = new WeakMap<object, WsClient>()
const pending  = new WeakMap<object, string[]>()

export default defineWebSocketHandler({
  open(peer) {
    // 读取浏览器 cookie 透传给后端（认证）
    const cookie = peer.request?.headers?.get?.('cookie'); if (cookie) headers.cookie = cookie
    const upstream = new WsClient(backendUrl(), { headers })
    sockets.set(peer, upstream); pending.set(peer, [])
    upstream.on('open', flush)     // 后端就绪后冲刷排队消息
    upstream.on('message', d => peer.send(d.toString()))
    upstream.on('close'|'error', () => peer.close())
  },
  message(peer, message) {
    const text = typeof message === 'string' ? message : (message.text?.() ?? String(message.rawData ?? ''))
    if (upstream OPEN) upstream.send(text); else pending.push(text)  // 排队防竞态
  },
  close(peer) { upstream.close(); cleanup }
})
```

### 3.5 hooks.listen 兜底隧道（dev 备胎）
当 CLI 没有把 upgrade 转发给 worker 时（老版本/异常环境），在 `listen` 钩子里对 `/ws` 做**原始 TCP 隧道**：`http.request` 携带原请求头（含 cookie）→ 收到 101 后回写状态行 + `socket.pipe` 双向对接。**条件挂载**（`server.listeners('upgrade').length > 0` 时不挂），避免与 crossws/CLI 双处理。

## 4. 代理注意点
- `/api/**` 通配：**新增 REST 端点无需改网络层**。
- `/signin` 不经过 devProxy（避免与后端 `/login` 页路由冲突）。
- cookie 全程只落在前端 origin；REST 代理自动携带，WS 靠中继手动转发。
