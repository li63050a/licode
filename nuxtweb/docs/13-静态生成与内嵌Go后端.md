# 13 · 静态生成与内嵌 Go 后端

> 这是 nuxtweb 的**第三种部署形态**：把前端静态化（`dist/`）后**内嵌进 Go 二进制**（`go:embed`），
> 替代后端自带的旧 HTMX 页面。用户运行单个二进制即获得完整新界面，**无需 Node 运行时、无需代理/中继**。

## 1. 三种形态对比

| 形态 | 命令/产物 | 运行时 | 网络模式 | 登录 |
| --- | --- | --- | --- | --- |
| 开发 | `npm run dev`（3000） | Node | 代理/中继到后端 | `/signin` 中继 |
| Node 生产 | `npm run build` → `.output/` | Node | 代理/中继到后端 | `/signin` 中继 |
| **静态内嵌** | `npm run generate` → `dist/` → `go:embed` | **仅 Go 二进制** | **同源直连** | 原生 form `POST /login` |

静态内嵌形态下：浏览器访问 `http://<host>:8080/` 时，页面由 Go 二进制直接吐出（Nuxt SPA），
`/api/*` 与 `/ws` 与页面**同源**，`useApi`（相对路径 fetch）与 `useLicode`（`location.host`）天然命中后端，
不需要任何 CORS、代理或 WS 中继。

## 2. 静态生成（nuxtweb 侧）

```bash
cd nuxtweb
npm run generate
# 产物输出到 dist/（约 470 KB，gzip 约 140 KB）
```

配置：`nuxt.config.ts` 中

```ts
nitro: {
  output: { publicDir: 'dist' },  // ★ 静态产物输出目录（默认 .output/public）
  experimental: { websocket: true }, // 仅 dev/build 生效，静态产物不含 server 逻辑
  // ...
}
```

产物结构：

```
dist/
├── index.html        # 主页 SPA 加载器（根路径 /）
├── 200.html          # 静态托管 SPA fallback（Go 内嵌时可选）
├── 404.html          # 同左
├── login/index.html  # 登录页 SPA 加载器（/login）
└── _nuxt/            # JS/CSS 产物（内容 hash 命名，可长缓存）
```

> 注意：`npm run generate` 输出 `ssr:false` 的 **SPA 加载器**（只有 `<div id="__nuxt">`），
> 页面内容由浏览器端 Vue 渲染，因此**不需要**任何 Node 进程就能运行——这正是内嵌的基础。

## 3. 内嵌到 Go 后端

### 3.1 产物落位与 embed

静态产物从 `nuxtweb/dist` 同步到 `internal/web/nuxt/`（构建脚本自动做，见 §4），
由 `internal/web/web.go` 嵌入：

```go
// ⚠ 必须用 all: 前缀！否则 embed 默认排除以 . 或 _ 开头的文件/目录，
// 整个 _nuxt/ 会被静默丢弃，页面表现为「HTML 能打开但 CSS/JS 404」。
//go:embed all:nuxt
var nuxtFS embed.FS

func NuxtFS() fs.FS {           // 挂载在 / 与 /_nuxt/ 下的前端文件系统
    sub, err := fs.Sub(nuxtFS, "nuxt")
    ...
}
func ReadNuxt(name string) ([]byte, error) { ... }   // 如 "login/index.html"
```

### 3.2 路由接线（cmd/serve.go）

| 路由 | 行为 |
| --- | --- |
| `GET /` | 先 `auth.require`；尝试 serve Nuxt 静态文件（`index.html`），**命中失败则 fallback `index.html`**（SPA 前端路由接管，如 `/login`、`/nonexistent` 都由它兜底） |
| `GET /_nuxt/*` | **不要求认证**，直接 serve 产物（登录页也是 SPA，必须能加载资源）；带内容 hash 可长缓存 |
| `GET /login` | `auth.handleLogin` → 返回 `login/index.html`（SPA 登录页），未启用密码时 302 → `/` |
| `POST /login` | 表单校验 → 成功 302 `/` + `Set-Cookie`；失败 302 `/login?error=1` |
| `/api/*`、`/ws` | 保持不变（同源直连即命中） |

核心 handler：

```go
// SPA fallback：非 /_nuxt、/api、/ws 的 GET 都回 index.html
mux.Handle("/", func(w, r) {
    if !auth.require(w, r) { return }
    nuxt := web.NuxtFS()
    p := strings.TrimPrefix(r.URL.Path, "/"); if p == "" { p = "index.html" }
    if f, err := nuxt.Open(p); err == nil { f.Close(); serveNuxtFile(w, r, nuxt, p); return }
    serveNuxtFile(w, r, nuxt, "index.html")   // SPA 兜底
})

func serveNuxtFile(w, r, nuxt, name) {
    // .html → Cache-Control: no-store（改版即时生效）
    // 其它 → Cache-Control: public, max-age=604800
    http.ServeFileFS(w, r, nuxt, name)
}
```

## 4. 构建与同步链路

`scripts/sync-nuxt.sh`（`build.sh` / `Makefile` 在编译前自动调用）：

```bash
# 1) 有 node 则重新生成：cd nuxtweb && npm run generate
# 2) 清空并复制：rm -rf internal/web/nuxt && cp -r nuxtweb/dist internal/web/nuxt
# 3) 无 node 时跳过 → 使用已提交的 internal/web/nuxt 产物（保证 go build 永远可用）
```

- `internal/web/nuxt/` **已提交到 git**（约 470 KB），克隆后无 node 也能直接 `go build`。
- 改了 nuxtweb 前端后，跑 `bash scripts/sync-nuxt.sh` 或直接 `npm --prefix nuxtweb run generate` + 手动拷贝，再重新编译 Go。

## 5. 登录在静态内嵌形态下的差异

静态产物**不含** `server/routes/signin.post.ts`（nitro server 路由），因此登录不走 `/signin`。
`pages/login.vue` 改为**原生表单提交**：

```vue
<form action="/login" method="post">
  <!-- v-model 同步到 hidden input，浏览器原生提交（跟随 302、自动保存 Set-Cookie） -->
  <input type="hidden" name="username" :value="username" />
  <input type="hidden" name="password" :value="password" />
  ...
</form>
```

- 浏览器原生 form 提交会**跟随 302 并保存 `Set-Cookie`** —— 恰好绕开 `$fetch` 跟随重定向丢 cookie 的坑（见 05 文档 §4），同源内嵌下无需 Node 中转。
- 密码错误：后端 302 到 `/login?error=1`，`login.vue` onMounted 读 `route.query.error` 显示「用户名或密码错误」。
- 登录成功 302 → `/` → 返回 Nuxt 主页，前端 `GET /api/auth` 确认后 `connect()`。

## 6. 开发/验证流程

```bash
# 后端改 Go 代码 → 直接编译（embed 目录已在 git，无需 node）
cd D:\code\licode

# 改了 nuxtweb 前端 → 刷新产物后重新编译
```

```bash

```

## 7. 已知坑速查

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 页面 HTML 能开但 CSS/JS 全 404 | `go:embed nuxt` 默认排除 `_` 开头目录 → `_nuxt/` 未进二进制 | embed 用 `all:nuxt` |
| `npm run generate` 报 `EBUSY .output` | 之前 `node .output/server/index.mjs` 进程/句柄占用 | 杀 node 进程后删 `.output` 再 generate |
| 登录页提交 `/signin` 404 | 静态产物不含 nitro server 路由 | 用原生 form `POST /login`（login.vue） |
| 内嵌后 `/login` 加载不到资源 | `/_nuxt/` 被 `auth.require` 拦截 | `/_nuxt/` 路由**不要求认证** |
| 改了前端重新编译没变化 | 浏览器缓存了 `index.html` | index.html 已设 no-store；强制刷新即可 |
