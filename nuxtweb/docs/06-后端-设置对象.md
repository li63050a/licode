## 2. 关键语义（前端必须理解）

### 2.1 厂商解析链
- `ActiveProvider()`：在 `providers[]` 中找 `provider == settings.provider` 的条目；找不到则回退顶层字段构造。
- `resolveType()`：`type` 归一——`ollama→openai`、`gemini→google`、`anthropic→claude`；`type` 空则按 `provider` 名推断（openai/ollama/custom→openai，claude/anthropic→claude，gemini/google→google），否则默认 openai（自定义厂商即 OpenAI 兼容）。
- `UpsertActive()` + `syncTopLevel()`：把激活厂商信息写回 `providers[]`，并把顶层 `base_url/api_key/model` 镜像成激活厂商的。
- `AIConfig()` = `ActiveProvider()` 转成 `ai.Config`；**`/api/models` 就用这个（重点是 key）**。

### 2.2 默认值（`finalize()`）
- provider 空 → `openai`。
- 风险工具默认询问：`tool_rules = {Write:ask, Shell:ask, Delete:ask}`（仅当 tool_rules/ask_tools/deny_tools 全空时）。
- `streaming` / `audit_enabled` / `audit_auto_fix` 为 **`*bool`**：null → true。
- audit 默认 `scan_dirs:["."]`、`exclude:[vendor,node_modules,.git,dist]`。
- temperature 0.7、max_tokens 4096、max_iterations 16。
- 审计默认开启。

### 2.3 保存链路（WS `settings_set` → `applyServerSettings`，`cmd/serve.go`）
```
json.Marshal(msg.Settings) → Unmarshal 到 Settings
→ EnsureDefaults()（finalize）
→ Validate() = ai.New(s.AIConfig())   // 未知类型归一，几乎不失败
→ NewClient()
→ st.settings = Snapshot(); st.client = client
→ st.settings.Save("")                 // 写回 ~/.licode/config.json
→ 回 settings 事件
```
- **settings_set 是整体替换**：前端必须拿 `settings` 事件的全量对象 → 改字段 → 原样回传，否则未表单化的字段（tool_rules、compaction、shutdown_timeout 等）会被清零。这是旧 UI 的一个 bug（设置对话框只回传部分字段导致丢配置）。

### 2.4 加载优先级
- `ConfigPaths()`：用户级 `~/.licode/config.json` + 工作目录 `licode.json`（项目级覆盖）。
- `applyEnv()`：环境变量覆盖。
- 启动 flags → ApplyFlags。

## 3. 前端设置表单映射（`SettingsDialog.vue`）

| 分组 | 字段 |
| --- | --- |
| 基础 | model、api_key、base_url、temperature、max_tokens、max_iterations、streaming、auto_allow、subagents、compaction、title_gen、cache_enabled |
| 厂商 | providers 列表增删改、激活、获取模型（`/api/models`）、新厂商添加 |
| 高级 | shell_path、sandbox_image、retry_max、sub_timeout、max_ctx_tokens、cache_ttl、tool_retry_max、shutdown_timeout、rag_source、ask_tools、deny_tools、audit_scan_dirs、audit_exclude、redact_secrets、sandbox、tool_auto_retry、rag_enabled、audit_enabled、audit_auto_fix、tool_rules 行编辑、mcp_servers（JSON 文本域） |

注意事项：
- 数字字段在 `buildSettings()` 用 `Number(x) || 0` 归一（`NUM_KEYS` 列表）。
- 逗号列表字段（ask_tools 等）用 `splitList` 转数组。
- `mcp_servers` 是 JSON 文本域 → `JSON.parse`，失败提示「MCP 服务器 JSON 格式无效」并阻止保存。
- 保存按钮在 `!state.settings`（设置未加载）或 `wsStatus !== 'connected'` 时禁用，避免空表单把真实配置冲掉。
- 厂商激活/获取模型：`activate(p)` 只改本地；`fetchModels` 会把目标厂商**临时设为激活**再调 `/api/models`（因为后端用激活厂商的 key），完成后由用户点保存生效。

## 4. 常见坑
1. `settings_set` 必须**全量**（见上）。
2. 不要在「获取模型」流程里把对话框其他未提交修改一并 `saveSettings`（历史 bug，已改：只基于当前 `state.settings` 快照切激活厂商）。
3. `streaming/audit_enabled/audit_auto_fix` 是 `*bool`：前端 `!!local.xxx` 绑定 Switch，回传用 `!!` 归一成布尔。
4. api_key 用 `<Input type="password">` 展示但不该明文回显成 `••••` 之外的形式（当前组件是明文回显，注意隐私）。
