## 2. 依赖与网络

- `go.mod`：`module licode`，`go 1.22`。
- 国内网络**必须**先设 Go 代理，否则依赖下载超时：

```bash
set GOPROXY=https://goproxy.cn,direct
```

- 纯 Go、无 CGO：`CGO_ENABLED=0`，产物可任意平台运行（含 Android/Termux，用 linux-arm64 产物）。

## 3. 构建与测试

```bash
cd D:\licode

# 编译检查
set GOPROXY=https://goproxy.cn,direct&& go build ./...

# 全部测试（含插件 wasm 端到端：echo/求和/读文件）

# 出可执行文件（示例放到临时目录）

# 交叉编译全部平台

```

## 4. 启动

```bash
licode [--host H] [--port P] [--addr A] [provider/key/model...] [--password PW] [--https] ...
```

### 4.1 启动参数（`cmd/serve.go` ServeOptions + cobra flags）

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--host` | 监听主机 | `127.0.0.1`（仅本机；局域网访问需 `0.0.0.0`） |
| `--port` | 端口 | `8080` |
| `--addr` | 直接指定监听地址（优先于 host/port） | - |
| `--provider` | 厂商标识 | `openai` |
| `--base-url` | API 地址 | 厂商默认 |
| `--api-key` | API 密钥 | 环境变量/空 |
| `--model` | 模型名 | 厂商默认 |
| `--username` | 登录用户名 | `licode` |
| `--password` | 登录密码；**非空才启用登录** | 空（无需登录） |
| `--https` | HTTPS（无证书时自动生成自签名到 `~/.licode/ssl/`） | 关 |
| `--tls-cert` / `--tls-key` | 指定证书/私钥 | - |
| `--no-subagents` | 禁用子代理编排 | 子代理开 |
| `-h/--help` | 简体中文帮助 | - |

### 4.2 环境变量

| 变量 | 作用 |
| --- | --- |
| `LICODE_PROVIDER` / `LICODE_BASE_URL` / `LICODE_API_KEY` / `LICODE_MODEL` | 同名参数 |
| `LICODE_USERNAME` / `LICODE_PASSWORD` | 登录凭据 |
| `LICODE_HOME` | 数据目录（默认 `~/.licode`） |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` | 各厂商标准密钥（`LICODE_API_KEY` 未设时按类型自动读取） |

优先级：**命令行 > 环境变量 > 配置文件 > 默认值**。

### 4.3 配置文件

- 用户级：`~/.licode/config.json`（首次启动自动生成；`settings_set` 修改后写回这里）。
- 项目级：工作目录下 `licode.json`（`ProjectConfigName`）可覆盖用户级。
- 服务器级：`config.toml`（首次启动生成；仅放服务器监听/TLS 等，**不放 AI 配置**）。
- 热重载：`SIGHUP` 重读 config.json 并重建客户端（Windows 上一般用不到）。

## 5. 数据目录 `~/.licode`（`internal/settings/dirs.go`）

`LICODE_HOME` 可整体覆盖；相对路径回退 `.licode`。

| 路径 | 用途 |
| --- | --- |
| `config.json` | 设置（providers/tool_rules/mcp_servers…），settings_set 落盘处 |
| `session.key` | HMAC 会话密钥（持久化 → 后端重启 cookie 仍有效） |
| `system-prompt.md` | 系统提示词（可直接编辑，首次自动生成默认内容） |
| `md/*.md` | 附加提示词：递归读取全部内容追加到系统提示词 |
| `skills/` | 技能（markdown frontmatter name/description → 注册为 `skill_<name>` 工具） |
| `plugins/` | WASM 插件（`<名>/<名>.wasm` + `<名>.json` 清单），fsnotify 热加载 |
| `mcp/` | MCP 服务器配置 |
| `sessions/` | 会话记录（每会话一个 json，实时保存） |
| `tools/` | 外部命令工具（fsnotify 热加载，注册进当前 Agent） |
| `search/index.json` | 联网搜索本地索引库 |
| `logs/licode.log` | 追加日志 |
| `cache/` | LLM 语义缓存（`cache_enabled` 时） |
| `ssl/` | HTTPS 自签名证书 |

## 6. 健康检查（`cmd/health.go`）

| 端点 | 认证 | 响应 |
| --- | --- | --- |
| `GET /health` | 无 | `{"status":"ok"}` |
| `GET /ready` | 无 | 就绪 `{"status":"ready"}`；关停中 503 `{"status":"shutting_down"}`；未就绪 503 `{"status":"not_ready","problems":[...]}` |

`problems` 探测项（15s 缓存）：
- `llm_unreachable`：对 `settings.base_url` 做 TCP 拨号（3s 超时）失败。
- `docker_unavailable`：`docker info` 探测失败（沙箱功能需要 Docker）。

## 7. 优雅关停

- 收到关停信号后：标记 `shuttingDown`（新 WS 客户端收到 `error`「服务正在关停」），等待运行中的 Agent/子代理/Shell 自然完成或超时（`shutdown_timeout`，默认 30s），然后退出。

## 8. 旧界面（内置前端）

- `internal/web` 通过 `go:embed` 打进二进制：`/` 服务 index.html，`/static/*` 静态资源（Cache 300s），`/fragment/*` HTMX 片段。
- 新前端（nuxtweb）不依赖这些路由，但**保留不动**作为兜底（访问 8080 即旧界面）。
- 旧界面的 `app.js`/模板是**新 API 的权威调用示例**，运维适配时优先参考（见 ops-guide §4.2）。
