# 09 · 前端：状态与数据流

## 1. useLicode —— 全局单例 Store（`composables/useLicode.ts`）

模块级 `let store` 单例（`useLicode()` 返回同一个），`reactive` 状态：

```ts
state = {
  wsStatus: 'connecting' | 'connected' | 'disconnected',
  sessions: [],                // SessionInfo[]
  sessionId: '',
  messages: [],                // ChatMessage[]
  busy: false, statusText: '',
  ask: null,                   // { askId, toolName, toolArgs } | null
  settings: null,              // Settings | null
  stats: { ... },              // StatsInfo
  settingsOpen: false,
  rightTab: '' | 'info' | 'files' | 'search' | 'audit',
  sidebarCollapsed: false,
  auditTick: 0,
}
```

### 数据结构
```ts
type Block = TextBlock | ToolBlock
TextBlock = { kind:'text', id, text }
ToolBlock  = { kind:'tool', id, name, args, out, running }
ChatMessage = { id, role:'user'|'assistant', blocks: Block[] }
```

### connect() / 重连
- 建立 `ws(s)://<host>/ws`；`onopen` → `settings_get` + `sessions_get`。
- `onclose` → `busy=false` + **2s 定时重连**（后端无心跳）。
- `send(type, payload)` 仅在 OPEN 时发送。

### handleEvent（服务端事件 → 状态映射）
| 事件 | 处理 |
| --- | --- |
| `delta` | `appendText(ensureAssistant(), content)`：确保最后一条是 assistant，追加到其最后一个 text 块 |
| `tool_start` | 在最后 assistant 消息推 `{kind:'tool', running:true, args}` |
| `tool_done` | 从消息块**反向**找最后一个 `running && name==toolName` 的块，写 `out`、`running=false` |
| `status` | `statusText = content` |
| `done` | `busy=false; statusText=''`；`sessions_get`（标题可能自动生成） |
| `error` | `busy=false`；`Message.error(error)` |
| `ask` | `state.ask = { askId, toolName, toolArgs }` |
| `settings` | `state.settings = evt.settings` |
| `sessions` | `state.sessions / sessionId` |
| `stats` | `Object.assign(state.stats, evt.stats)` |
| `audit_log` | `auditTick++`（审计面板刷新）+ `JSON.parse(content)` 弹摘要 toast |

### 动作
| 方法 | 行为 |
| --- | --- |
| `sendMessage(content)` | 空/busy 忽略；`/clear` 本地清空 + 发送；否则 push 用户消息 + 空 assistant、`busy=true`、发 `message` |
| `interrupt()` | 发 `interrupt` |
| `replyAsk(approve, always)` | 发 `ask_reply`，清 ask |
| `newSession()` / `switchSession(id)` / `renameSession` / `deleteSession` / `branchSession` | 对应 session_*；切换清空本地 messages |
| `saveSettings(next)` | 全量 `settings_set`（**必须整体替换**） |
| `clearMessages()` | 清本地消息 |

## 2. useApi —— REST 封装（`composables/useApi.ts`）
```ts
export async function useApi<T>(path, opts) {
  fetch(path, { ...opts, headers: { Accept:'application/json', ... } })
  // 401 → navigateTo('/login') + throw
  // 非 JSON 响应：尝试 JSON.parse，否则原文
  // JSON 且 !ok → throw data.error
}
```
- 约定：所有 `/api/*` 调用走它；下载/上传走原生 fetch。

## 3. useTheme（`composables/useTheme.ts`）
- `mode`（useState）；`initTheme()` 读 `localStorage['licode_theme']` 设置 `html.dark` 类；`toggleTheme()`。
- 与 fuxsto 内置 `.dark` 主题联动。

## 4. markdown 渲染器（`utils/markdown.ts`）
- `renderMarkdown(src)`：先抽出 ``` 围栏代码块（占位符），再 HTML 转义 → 行内 `code`/`**bold**`/`*italic*`/`[link](http)` → 行级 `#`标题 / `-`,`1.`列表 / `>` 引用 / 段落。
- 代码块输出 `<div class="md-pre">…<button class="md-copy" data-code="encodeURIComponent(code)">复制</button>`；点击复制由 ChatArea 事件委托 `decodeURIComponent(dataset.code)` → clipboard。
- `prettyArgs(jsonStr)`：可解析则 `JSON.stringify(…, null, 2)`，否则原样（工具参数展示）。

## 5. 数据流示例

### 发送一条消息
```
ChatInput doSend → licode.sendMessage(text)
  → push 用户消息 + 空 assistant（UI 立即显示）
  → WS message
  → 后端流式回：status / tool_start / tool_done / delta / stats / done
  → handleEvent 逐条更新 state → 组件响应式渲染（自动滚动由 ChatArea watch 处理）
  → done → sessions_get 刷新标题
```

### 保存设置
```
SettingsDialog.save()
  → 前置守卫：state.settings 存在 && wsStatus==='connected'
  → buildSettings()：基于 state.settings 深拷贝 → 改字段 → 全量对象
  → licode.saveSettings → WS settings_set
  → 后端校验/落盘 → 回 settings 事件 → state.settings 更新
  → 关闭对话框 + toast
```

### 权限询问
```
后端发 ask → state.ask 设置 → AskBar 渲染「工具 X 请求执行」
  → 用户点 拒绝/允许/始终允许 → replyAsk → WS ask_reply
  → 后端继续执行（允许）或取消（拒绝）
```
`auto_allow:true` 时后端**不发 ask**（直接执行）。

## 6. 关键约定
1. `settings_set` 永远**全量**。
2. `sessions` 事件后不依赖历史消息（后端不提供）。
3. WS 断开时发送会**静默失败**——保存类操作先检查 `wsStatus`（SettingsDialog 已做）。
4. `stats.provider/model` 为空 → 显示 `settings` 兜底。
