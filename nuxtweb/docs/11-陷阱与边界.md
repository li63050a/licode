# 11 · 陷阱与边界

> 静态内嵌形态下的已知坑。每条都给：现象 / 根因 / 修复 / 位置。

## A. 构建 / 渲染层

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 1 | 页面**纯文本无样式** | 没启用 `@tailwindcss/vite`，`@import "tailwindcss"` 无法解析，整份 CSS 加载失败 | `vite.plugins:[tailwindcss()]` | nuxt.config |
| 2 | 大量 `Failed to resolve component: Button/Input/...` | fuxsto 组件没 import；Nuxt 不自动注册 node_modules 组件；**vue-tsc 默认不报未知组件** | 每个 SFC 顶部显式 `import { ... } from 'fuxsto-design'` | 所有组件 |
| 3 | 页面空白（早期版本） | `index.vue` 用 `v-if="ready"` 门控整个 UI，后端不可达时 `ready` 永远 false | 改为始终渲染 + ConnectionBanner | index.vue |
| 4 | `[esbuild css minify] Expected ";" but found "}"` 警告 | Tailwind v4 的 `@layer utilities{@tailwind utilities}` 与 esbuild 兼容告警 | **无害，忽略** | - |

| # | 边界 | 说明 |

## F. 后端新增功能 → 前端适配清单

> 后端仓库（`li63050a6/licode` 的 `beta` 分支）每新增一个能力，前端按下面分类型适配。**改完必须重新生成静态产物并重新编译 Go**（见 §F7）。

### F1. 新增 REST 端点
1. 直接调 `useApi<T>(path, opts)`（相对路径，静态内嵌同源直连，无需 CORS/代理改动）。
2. 端点契约见 [03-后端-REST-API参考](03-后端-REST-API参考.md)；字段名必须与后端**逐字一致**（大小写敏感，见 §E32）。
3. 在对应组件中调用并渲染；新增面板则在 `RightPanel` 加 tab + `pages` 或 `components` 新增。
4. 类型：在调用处定义接口类型（无集中 schema，参考后端返回示例）。

### F2. 新增 WS 服务端事件
1. 在 `useLicode.handleEvent` 的 `switch(evt.type)` 加 `case`。
2. 需要驱动 UI 的状态：在 `createStore` 的 `state` 加字段，事件到达时更新。
3. 需要展示：新增/扩展组件；复杂交互可在 `components/` 建组件。

### F3. 新增 WS 客户端消息
- 直接 `send(type, payload)`（`useLicode` 已封装），无需改协议层。
- 若消息影响会话/统计，处理后可能需要重新 `sessions_get` / 等 `stats` 事件。

### F4. 新增设置字段（`~/.licode/config.json`）
1. `Settings` interface（`composables/useLicode.ts`）加字段。
2. `SettingsDialog` 加表单控件（fuxsto 组件显式 import；可选布尔用 `:model-value="!!x"` + `@update`，见 §C18）。
3. **保存必须基于 `state.settings` 全量 patch 后回传**：`settings_set` 是整体替换，只回传表单字段会清掉其他字段（见 §B5）；WS 未连接时保存按钮已禁用。

### F5. 新增 Agent 工具（工具调用）
- 工具调用由 `tool_start`/`tool_done` 事件**通用渲染**（ToolBlock 折叠卡片），通常**无需改动前端**。
- 仅当需要参数/结果的定制展示时才改 `ToolBlock.vue`。

### F6. 新增页面/路由
- 在 `pages/` 下新建 `.vue` 即自动路由；SPA fallback 由 Go 端兜底（`index.html`），无需改后端路由。

### F7. 改完必须重生成静态产物
```bash
cd D:\code\licode\nuxtweb
npm run generate                  # 产出 dist/
cd .. && bash scripts/sync-nuxt.sh   # 同步 dist → internal/web/nuxt
go build -o licode.exe .          # 重新编译
```

### F8. 验证
- `npx nuxt typecheck` 0 error；
- 静态冒烟：`/` 回 Nuxt 壳、`/_nuxt` 200、`/api/*` 返回 JSON（见 [12-验证与调试](12-验证与调试.md) §3）；
- 功能级验证：无头浏览器或手动跑一遍新功能对应流程。

### F9. 最新功能适配对照（beta 已内置，改后端时对照更新）
| 后端能力 | 前端位置 | 说明 |
| --- | --- | --- |
| 会话历史回放（`session_history`/`history`） | `useLicode.ts` `case 'sessions'` 发拉取、`case 'history'` 经 `historyToMessages` 重建 | 竞态由 `sessionId` 校验兜底 |
| 厂商模型增删（`ProviderConfig.Models`） | `SettingsDialog.vue` 厂商行 `models` Chip 增删；`useLicode.ts` `ProviderConfig.models` | 删除当前 `model` 会在 `UpsertActive` 时被 `AddModel` 加回（见 06 §4-6） |
| DNS 多服务器容灾（`Settings.DNS.Servers[]`） | `SettingsDialog.vue` DNS 分组（mode 下拉 + server + 预设）；`useLicode.ts` `DNSConfig` | `settings_set` 时 `dns` 也是整体替换，删空回落系统默认 |
