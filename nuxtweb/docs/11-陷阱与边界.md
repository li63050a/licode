# 11 · 陷阱与边界

> 静态内嵌形态下的已知坑。每条都给：现象 / 根因 / 修复 / 位置。

## A. 构建 / 渲染层

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 1 | 页面**纯文本无样式** | 没启用 `@tailwindcss/vite`，`@import "tailwindcss"` 无法解析，整份 CSS 加载失败 | `vite.plugins:[tailwindcss()]` | nuxt.config |
| 2 | 大量 `Failed to resolve component: Button/Input/...` | fuxsto 组件没 import；Nuxt 不自动注册 node_modules 组件；**vue-tsc 默认不报未知组件** | 每个 SFC 顶部显式 `import { ... } from 'fuxsto-design'` | 所有组件 |
| 3 | 页面空白（早期版本） | `index.vue` 用 `v-if="ready"` 门控整个 UI，后端不可达时 `ready` 永远 false | 改为始终渲染 + ConnectionBanner | index.vue |
| 4 | `[esbuild css minify] Expected ";" but found "}"` 警告 | Tailwind v4 的 `@layer utilities{@tailwind utilities}` 与 esbuild 兼容告警 | **无害，忽略** | - |

## B. 协议 / 数据层

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 5 | 保存设置后部分字段被清零 | `settings_set` 是**整体替换**；只回传表单字段会清掉 `tool_rules`/`compaction`/`shutdown_timeout` 等 | 基于 `state.settings` 全量对象 patch 后回传 | SettingsDialog.save / useLicode |
| 6 | 设置保存「没反应/保存后被重置成默认」 | 保存时 `state.settings` 为 null（WS 未就绪）→ 用空对象提交 | 保存按钮在 `!state.settings || wsStatus!=='connected'` 禁用并提示 | SettingsDialog |
| 7 | 给新厂商「获取模型」失败/401 | `/api/models` 用**激活厂商的 api_key**，query 只覆盖 type/base/provider | 先 `settings_set` 把目标厂商设为激活再取列表 | SettingsDialog.fetchModels |
| 8 | token 显示恒为 0 | 旧 UI 读 `stats.tokens`，后端给的是 `stats.context_tokens` | 前端读 `context_tokens`/`context_pct` | InfoPanel |
| 9 | `stats.provider/model` 恒为空 | 后端就这么实现 | 前端回退 `settings.provider/model` | InfoPanel / TopBar |
| 10 | 切换会话后看不到历史 | 后端每次连接是**全新会话管理器**、无历史 API | 前端约定：切换即清空本地 messages | useLicode.switchSession |
| 11 | `/api/upload` 返回的 `url` 打不开 | 旧版 `url` 指向不存在的 `/uploads/*` 路由 | 只信返回的 `path`（绝对路径） | FilesPanel |
| 12 | `audit_log` 事件 toast 显示对象 | `content` 是 **JSON 字符串** | 先 `JSON.parse(content)` | useLicode.handleEvent |
| 13 | 复制代码按钮失效 | 代码含特殊字符，直接放 data 属性被截断 | `encodeURIComponent(code)` + `decodeURIComponent` | markdown.ts |

## D. 静态生成与内嵌（go:embed）

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 19 | 页面 HTML 能开但 CSS/JS 全 404 | `go:embed nuxt` 默认排除以 `.`/`_` 开头的文件/目录 → 整个 `_nuxt/` 未进二进制 | embed 用 `all:nuxt` | internal/web/web.go |
| 20 | `npm run generate` 报 `EBUSY: .output` | 之前 `node .output/server/index.mjs` 进程/文件句柄占用 | 杀 node 进程 → 删 `.output` → 重新 generate | - |
| 21 | 内嵌后登录提交 `/signin` 404 | 静态产物**不含** nitro server 路由 | `login.vue` 改原生 form `POST /login`（浏览器跟随 302 保存 cookie） | pages/login.vue |

| 23 | 改了前端重新编译没变化 | 浏览器缓存旧 `index.html` | index.html 已设 `Cache-Control: no-store`；强制刷新即可 | cmd/serve.go |

## E. 后端行为边界（前端只能适配）

| # | 边界 | 说明 |
| --- | --- | --- |
| 24 | 无心跳/无 ping-pong | 前端 2s 自动重连；`ping` 消息后端不处理 |
| 25 | busy 锁 | 一条消息处理中再发 `message` → `error`「上一条消息仍在处理中」 |
| 26 | `message` 队列满(50)/发送队列满(256) | 前端会收到 `error`「消息队列已满」/事件静默丢弃 |
| 27 | `/clear` | 是 `message` 特殊值，服务端清当前会话并回 `done` |
| 28 | 会话标题 | `title_gen` 开启时由 LLM 生成，`done` 后需重新 `sessions_get` |
| 29 | 模型不调用工具 | 如 deepseek-v4-flash 可能只回文本不写文件；**不是前端 bug**，ask 流程测试需注意 `auto_allow:true` 会跳过询问 |
| 30 | 搜索需出网 | bing/baidu/ddg 被墙时搜索失败；`local=only` 可离线查本地库 |
| 31 | 体积限制 | 文件写 ≤1MB、上传 ≤256MB、导入 ≤64MB |
| 32 | 请求体大小写敏感字段 | 前端与后端字段名必须逐字一致（`askId/askApprove/askAlways/sessionId/index/toolName/toolArgs/toolOut`） |
| 33 | Origin 校验 | 后端 WS CheckOrigin 放行；静态内嵌同源，无需前端处理 CORS |

## F. 结论性提醒
- **新增后端端点**：前端一般只需加 `useApi` 调用（相对路径同源直连）。
- **新增 WS 事件**：`useLicode.handleEvent` 加 case + 必要时新增 UI。
- **设置字段变更**：`SettingsDialog` 加表单 + 保持全量回传。
- **改了前端**：`npm run generate` → `bash scripts/sync-nuxt.sh` → 重新 `go build`（见 13 文档）。
