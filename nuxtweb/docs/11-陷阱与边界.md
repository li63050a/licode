# 11 · 陷阱与边界

> 本项目从零到可用的**全部已知坑**。每条都给：现象 / 根因 / 修复 / 位置。
> 运维人员在适配新版本后端时，先扫一遍本文 + [ops-guide §7](ops-guide.md)。

## A. 构建 / 渲染层

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 1 | 页面**纯文本无样式** | 没启用 `@tailwindcss/vite`，`@import "tailwindcss"` 无法解析，整份 CSS 加载失败 | `vite.plugins:[tailwindcss()]` | nuxt.config |
| 2 | 大量 `Failed to resolve component: Button/Input/...` | fuxsto 组件没 import；Nuxt 不自动注册 node_modules 组件；**vue-tsc 默认不报未知组件** | 每个 SFC 顶部显式 `import { ... } from 'fuxsto-design'` | 所有组件 |
| 3 | 页面空白（早期版本） | `index.vue` 用 `v-if="ready"` 门控整个 UI，后端不可达时 `ready` 永远 false | 改为始终渲染 + ConnectionBanner | index.vue |
| 4 | `[esbuild css minify] Expected ";" but found "}"` 警告 | Tailwind v4 的 `@layer utilities{@tailwind utilities}` 与 esbuild 兼容告警 | **无害，忽略** | - |

## B. 网络 / 代理层

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 5 | `/api/auth` 等经代理返回 **HTML**（旧界面） | nitro devProxy 是挂载点语义，**剥掉前缀**：`/api/auth`→`/auth`，命中 `/` 兜底 | target 写成 `${backend}/api`（让 httpxy 拼回前缀） | nuxt.config devProxy |
| 6 | WS 一直 **1006** 打不开 | dev 下 CLI 外层服务器默认不转发 upgrade；`devProxy.ws:true` 无效（devProxy 只调 `proxy.web`） | `nitro.experimental.websocket:true` + crossws 中继路由 `server/routes/ws.get.ts` | nuxt.config / ws.get.ts |
| 7 | 登录**总是**「用户名或密码错误」（密码正确） | 后端在 **302 上设置** `licode_auth`；`$fetch` 跟随重定向后拿不到中间响应头 → cookie 丢失 | `signin.post.ts` 用 Node `http.request`（不跟随 302）读 `set-cookie` 并回传 | server/routes/signin.post.ts |
| 8 | 登录成功但后端日志**没有「客户端已连接」** | 没有有效 cookie → WS upgrade 401（后端不给日志）；本质同 #7 | 修复 #7；并确保 `ws.get.ts` 透传 `peer.request.headers.cookie` | 05、08 文档 |
| 9 | hooks 兜底隧道与 CLI 转发**双处理** → WS 帧损坏 | `listen` 钩子无条件挂 upgrade 隧道，与 CLI 的转发同时写 socket | 条件挂载：`server.listeners('upgrade').length > 0` 时不挂 | nuxt.config hooks |
| 10 | 中继丢首条消息 | 后端 WS 客户端连接是异步的，先到的消息发送时上游还没 open | `pending` 队列缓冲，`upstream.on('open')` 后 flush | ws.get.ts |
| 11 | 生产（`node .output`）REST 404 | devProxy 只在 dev 生效 | `routeRules: {'/api/**':{proxy: backend+'/api/**'}}` | nuxt.config |

## C. 协议 / 数据层

| # | 现象 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- | --- |
| 12 | 保存设置后部分字段被清零 | `settings_set` 是**整体替换**；只回传表单字段会清掉 `tool_rules`/`compaction`/`shutdown_timeout` 等 | 基于 `state.settings` 全量对象 patch 后回传 | SettingsDialog.save / useLicode |
| 13 | 设置保存「没反应/保存后被重置成默认」 | 保存时 `state.settings` 为 null（WS 未就绪）→ 用空对象提交 | 保存按钮在 `!state.settings || wsStatus!=='connected'` 禁用并提示 | SettingsDialog |
| 14 | 给新厂商「获取模型」失败/401 | `/api/models` 用**激活厂商的 api_key**，query 只覆盖 type/base/provider | 先 `settings_set` 把目标厂商设为激活再取列表 | SettingsDialog.fetchModels |
| 15 | token 显示恒为 0 | 旧 UI 读 `stats.tokens`，后端给的是 `stats.context_tokens` | 前端读 `context_tokens`/`context_pct` | InfoPanel |
| 16 | `stats.provider/model` 恒为空 | 后端就这么实现 | 前端回退 `settings.provider/model` | InfoPanel / TopBar |
| 17 | 切换会话后看不到历史 | 后端每次连接是**全新会话管理器**、无历史 API | 前端约定：切换即清空本地 messages | useLicode.switchSession |
| 18 | `/api/upload` 返回的 `url` 打不开 | 旧版 `url` 指向不存在的 `/uploads/*` 路由 | 只信返回的 `path`（绝对路径） | FilesPanel |
| 19 | `audit_log` 事件 toast 显示对象 | `content` 是 **JSON 字符串** | 先 `JSON.parse(content)` | useLicode.handleEvent |
| 20 | 复制代码按钮失效 | 代码含特殊字符，直接放 data 属性被截断 | `encodeURIComponent(code)` + `decodeURIComponent` | markdown.ts |

## E. 后端行为边界（前端只能适配）

| # | 边界 | 说明 |
| --- | --- | --- |
| 27 | 无心跳/无 ping-pong | 前端 2s 自动重连；`ping` 消息后端不处理 |
| 28 | busy 锁 | 一条消息处理中再发 `message` → `error`「上一条消息仍在处理中」 |
| 29 | `message` 队列满(50)/发送队列满(256) | 前端会收到 `error`「消息队列已满」/事件静默丢弃 |
| 30 | `/clear` | 是 `message` 特殊值，服务端清当前会话并回 `done` |
| 31 | 会话标题 | `title_gen` 开启时由 LLM 生成，`done` 后需重新 `sessions_get` |
| 32 | 模型不调用工具 | 如 deepseek-v4-flash 可能只回文本不写文件；**不是前端 bug**，ask 流程测试需注意 `auto_allow:true` 会跳过询问 |
| 33 | 搜索需出网 | bing/baidu/ddg 被墙时搜索失败；`local=only` 可离线查本地库 |
| 34 | 体积限制 | 文件写 ≤1MB、上传 ≤256MB、导入 ≤64MB |
| 35 | 请求体大小写敏感字段 | 前端与后端字段名必须逐字一致（`askId/askApprove/askAlways/sessionId/index/toolName/toolArgs/toolOut`） |
| 36 | cookie 域 | 登录 cookie 只在前端 origin；直连后端 API/WS 会 401（必须走代理/中继） |
| 37 | Origin 校验 | 后端 WS CheckOrigin 放行，无需前端处理 CORS（同源代理） |

## F. 结论性提醒
- **新增后端端点**：前端一般只需加 `useApi` 调用（`/api/**` 代理通配）。
- **新增 WS 事件**：`useLicode.handleEvent` 加 case + 必要时新增 UI。
- **设置字段变更**：`SettingsDialog` 加表单 + 保持全量回传。
- **先看旧界面** `internal/web/static/app.js` 怎么调新 API（最权威的调用示例）。
